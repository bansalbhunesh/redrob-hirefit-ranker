# Study Φ — Reflexivity Log

Researcher assumptions and decisions that could bias interpretation (single coder).

- Going in, I expected recruiters to be stricter on integrity than engineers. The pilot
  covers ONLY Hacker News (engineer/founder-skewed), so the strong capability-first lean
  (53% QUALITY_FIRST) is partly a STRATUM artifact, not evidence recruiters agree. Flagged
  throughout; the recruiter stratum is the priority for the full study.
- "VERIFY_FIRST vs QUALITY_FIRST" was sometimes ambiguous (a comment praising work-samples
  may implicitly verify). Coding rule applied: if the unit's PRIMARY recommended action is a
  check/probe -> VERIFY_FIRST; if it elevates demonstrated capability over stated history ->
  QUALITY_FIRST. This rule was set before coding and held constant.
- The technology-anachronism mapping is the decision-critical one and I am motivated to find
  that humans tolerate it (it would vindicate the (B)-leaning read). To counter that bias I
  coded the strongest available counter-signal (HN_5924518) as VERIFY (not ignore) and kept
  the strict-on-minor outlier (HN_2246385). Only 3 items touch this class — too few to
  conclude; recorded as directional only.
- Conditionality coded LOW (5%) because HN comments are stylistically categorical; the real
  conditioning shows up in the SEVERITY x ACTION surface, not in explicit "it depends" phrasing.
  I therefore lead with the severity surface, not the conditionality count.
- No code definitions were changed mid-pilot (n=19); if the full corpus forces a change, all
  earlier items must be recoded and the codebook version bumped.
